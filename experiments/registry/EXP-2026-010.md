## Scientific claim and critical review

- **Claim.** Training the mask stream with a cavity class makes the image stream respond to that class. With a
  supplied scenario mask that labels the core as cavity, the generated T1ce in the core moves toward fluid signal
  more than with the same scenario without the class, beyond the seed spread.
  - Today's model gives no such class. In W4 its mask stream keeps its empty start (EXP-2026-007).
- Why it might matter:
  - The cavity becomes a labelled, controllable object for later scenarios (fluid now, other contents later).
  - A downstream segmenter gets a cavity label to learn the wall against.
- Null and alternatives:
  - The image stream ignores the mask. D2 item 9 found that a fixed mask did not brighten residual pieces: the
    start dominated. That is the most likely outcome, and the primary test is built to detect it.
  - The scaffold already darkens the core, so any agreement in ordinary W4 is trivial. The test therefore starts
    from a core that is not dark.
  - The class may teach "dark CSF anywhere": v2's fluid-like class puts a median 44% outside the core, possibly in
    sulci and ventricles. Decision 1 limits the class.
- What stays frozen: E0's recipe (1,000 steps, optimizer, seed 2026, the shared step-0 weights), RHUH's split,
  E-eval, and LUMIERE out of training.
- One change: the post-op mask targets of the 24 training patients gain the cavity class in the unused ID-1 channel.
  - The codec gives IDs 1, 2 and 3 one channel each, and RHUH's post-op labels never use ID 1.
  - The class name in the prompts follows decision 2.
- Inputs at inference: the pre-op inputs and the supplied scenario. The scenario's start mask labels the pre-op core
  as cavity (decision 4). No post-op data is read.

## Design

- **Targets.** For each training patient, computed in the training notebook from the processed post-op T1, T1ce
  and T2 on Drive:
  - v2's fluid-like voxels, restricted by decision 1, written as ID 1;
  - experts' IDs 2 and 3 unchanged.
  - A target that would overwrite an expert label is refused.
- **Training.** As E0s and E3m: the same step-0 state, seed 2026, 1,000 steps, the per-cohort log, lineage, and the
  memorization check.
- **Primary test: does the image respond to the class?**
  - Patients: the 3 RHUH validation patients and the 4 LUMIERE development patients. The test reads generated
    images only, so LUMIERE needs no post-op label.
  - Start image: the core filled at level f = 0.5 (`cavity_level`), halfway between the dark fill and the brain
    level, so the core is not dark at the start.
  - Two arms with the mask held fixed:
    - A: the scenario mask with the core as cavity (ID 1);
    - B: the same mask with the core as background.
  - Seeds 11, 22 and 33; the start t = 501; the same noise in both arms.
  - Readout: the median generated T1ce in the core, B minus A, per patient (mean of the seeds).
  - Run for the new model and for E0. E0 never learned a post-op ID 1, so its response is the reference.
- **Secondary:**
  - free-mask W4: the share of the core that the mask stream labels as cavity;
  - E-eval as frozen in EXP-2026-007, against E0 with E0s as the comparator. The new model must not be worse
    beyond the comparator, and the no-enhancing guardrail holds;
  - W7 kept share and precision.
- **Rule (proposal, decision 5):**
  - PROMOTE needs:
    - the new model's pooled B − A to exceed both E0's B − A and the seed spread, with its stratified bootstrap
      interval above 0;
    - no secondary guardrail failing.
  - REJECT if the response is no larger than E0's, or a guardrail fails.
  - INCONCLUSIVE otherwise.
- Budget: about 12 minutes of CPU for the targets in Colab, 45 minutes of training and about 2 hours of evaluation
  on the G4. The E-eval of E0 is reused; the primary test adds 2 models × 2 arms × 7 patients.

## Decisions for the researcher

| # | Decision | Recommendation |
|---|---|---|
| 1 | Which voxels get the cavity class | v2's fluid-like voxels inside the pre-op core + 2 mm only: this drops CSF in sulci and ventricles. The researcher's review of the v2 fluid pages can replace this limit |
| 2 | The prompt word for ID 1 | "resection cavity" in place of "necrosis", in a new config. Text did not control classes in Test A, so this mainly avoids a wrong word |
| 3 | Blood-like class | Not used: stopped by EXP-2026-009's frozen rule |
| 4 | Scenario start mask at inference | The pre-op core as cavity (ID 1) in place of background; residual pieces as now |
| 5 | Primary test and rule | As above: arms A and B with a fixed mask, a non-dark start (f = 0.5), the response against E0 |
| 6 | Order | The training notebook first; then the test and E-eval in one evaluation notebook, each with a CPU dry run first |
| 7 | Hard or soft cavity target | Soft, as the researcher proposed on 2026-11-28: the fluid rule has no expert check, so its confidence should show in the target. Value p = cap × ramp(T1) × ramp(T2), where each ramp is a logistic step at the frozen threshold (z(T1) −1.5, z(T2) +1.5) of width 0.5 z, and cap = 0.8 marks the label as rule-derived. It is written into the ID-1 channel as 2p − 1; the other channels stay ±1. The values are fixed before the run and are not tuned |
| 8 | A gate before training (for decision 7) | In the training notebook, before any step: a VAE round trip of the soft targets on the training slices. Stop if the ID-1 channel's mean absolute error over cavity voxels exceeds 0.1, or its correlation with the target falls below 0.9 |

- Notes on decision 7 (Claude, 2026-11-28):
  - A soft target lowers the penalty for wrong voxels near the thresholds. It does not fix systematic errors; for
    example, CSF in sulci is fluid with high confidence. Decision 1's spatial limit handles those.
  - The class stays `rule_derived` in every record (AGENTS.md provenance) and is never called ground truth.
  - Readouts read the ID-1 channel's decoded value in the core directly: the codec's argmax with a 0.5 threshold
    would hide values under 0.5.
  - The scenario mask at inference labels the core with the full value (1), because the scenario asserts the
    cavity.
  - Step 1 of EXP-2026-009 found that the VAE keeps cross-channel differences poorly in images. The masks already
    use one channel per class (the representation gate passed), but a graded channel is untested; decision 8
    checks it.

## Implementation (2026-11-28)

- Code:
  - `codec.encode_soft_cavity_channels` writes `2p − 1` into the ID-1 channel. It refuses an ID 1 in the label and
    any `p > 0` on a labelled voxel.
  - `training.build_feature_cache` takes an optional `cavity_soft`. Without it, the result is unchanged; the
    related suites passed. With it, a slice's prompt names the cavity where `p ≥ 0.5`.
  - `cavity_targets`: the soft target in the frame and on the working grid, the text override, and the round-trip
    gate (pooled MAE and Pearson over `p > 0` voxels, from the decoded posterior mean of the cached mask latents).
  - `cavity_test`: the test inputs, arms A and B, the core median, and the decision.
  - `configs/experiments/EXP-2026-010.json`.
- Notebooks:
  - `notebooks/RHUH_GBM_Colab_k1_train.ipynb`: targets from the processed post-op files on Drive (the moved T1ce
    must reproduce each export), the cache, the gate, lineage, training and the record. Training does not start if
    the gate fails.
  - `notebooks/RHUH_GBM_Colab_k1_test.ipynb`: the primary test for E0 and K1, the record and the decision.
- Details fixed while implementing, within the approved decisions:
  - Both arms and both models use the same prompts: the cavity scenario, with ID 1 named "resection cavity". Only
    the fixed mask differs between A and B.
  - The test slab is the 12 slices with the largest core (`choose_slab`), not every slice that touches `E`. This
    keeps the test near 1.5 GPU hours.
  - The decision reads PROMOTE_PENDING_GUARDRAILS until K1's E-eval has run.
- Change to decision 6, proposed for the researcher: K1's E-eval (guardrails, and the free-mask readout from its W4
  stacks) runs in a second session, and only if the primary test is not REJECT. This saves about 2 GPU hours when
  the image does not respond.
- Tests actually run (local, CPU):
  - `test_cavity_k1.py` (11) with the E-eval and E-series suites: 42 passed;
  - the codec, training-loop, sampler, model, localized wiring and sampling, and cavity-level suites: 89 passed.
- Static checks of both notebooks: every cell parses, project imports exist, no output, no ID, no config name
  rebound.
- Dry runs on the CPU with tiny random models; their numbers are not evidence:
  - training: data, train and save cells on 2 real training patients, with targets from the real processed files.
    The gate correctly failed on the random VAE (MAE 0.51); 2 steps were trained and the record written;
  - test: loop, save and confirm cells on 1 real validation export.
